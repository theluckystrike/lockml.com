Data Poisoning Attacks

Data poisoning is an attack where an adversary manipulates training data to degrade model performance or inject backdoors. The attacker either has direct access to training data or can influence it through data collection processes.

Attack Types:

  • Untargeted/Availability Attack: Degrade overall model accuracy for all inputs
  • Targeted/Backdoor Attack: Misclassify specific trigger-labeled samples while maintaining accuracy on clean data
  • Clean-Label Attack: Poison data with correct labels but adversarial features (harder to detect)
  • Dirty-Label Attack: Mislabel poisoned samples (easier to execute but easier to detect)

Key Factors:

  • Model Complexity: More complex models (Transformers, CNNs) are generally more vulnerable to poisoning
  • Poisoning Ratio: Higher percentage of poisoned data = greater impact (usually sublinear)
  • Attack Gradient: Knowledge of model architecture enables more efficient attacks
  • Model Capacity: Smaller models may degrade faster; very large models may be more robust

Defense Strategies:

  • Data Validation: Inspect training data for anomalies using statistical tests
  • Robust Training: Use adversarial training or certified defenses
  • Outlier Detection: Remove statistically unusual samples from training set
  • Model Ensemble: Combine multiple independently trained models
  • Differential Privacy: Add noise to gradient updates during training
  • Trigger Detection: Test model for backdoor patterns using reverse-engineering techniques
