Homomorphic Encryption for ML

Homomorphic Encryption (HE) enables computation on encrypted data without decryption. This allows cloud providers or untrusted third parties to perform ML inference on encrypted inputs while maintaining privacy. The tradeoff is significant computational and memory overhead.

HE Schemes:

  • BFV (Brakerski-Fan-Vercauteren): Supports exact integer arithmetic. Good for discrete operations. Slower but precise.
  • CKKS (Cheon-Kim-Kim-Song): Supports approximate floating-point arithmetic. Better for neural networks. Faster with slight precision loss.
  • TFHE (Torus Full Homomorphic Encryption): Fast bootstrapping for gate-level operations. Good for small circuits but slower for large ML models.

Key Parameters:

  • Polynomial Degree (N): Larger N = higher security but slower operations. Typical: 2048-8192.
  • Security Level: 128-bit is standard, 192/256-bit for long-term security. Larger = bigger ciphertexts.
  • Multiplicative Depth: Number of sequential multiplications before relinearization. Limits circuit depth.
  • Noise Budget: Decreases with each operation. Bootstrapping required if noise grows too large.

Typical Overhead:

  • Ciphertext Size: 10-100x larger than plaintext (depends on N and security level)
  • Addition: 100-1000x slower than plaintext
  • Multiplication: 1000-10000x slower than plaintext (with relinearization)
  • Bootstrapping: 10-100ms per call (reset noise budget)

Practical Considerations:

  • Best for inference, not training (which requires many multiplications)
  • Requires careful circuit design to minimize depth
  • Bootstrapping is expensive; avoid if possible
  • Approximate schemes (CKKS) work well for ML due to natural error tolerance
  • Batch processing multiple inputs can amortize costs
