Model Inversion & Gradient Leakage

Model inversion attacks reconstruct training data from shared gradients. The Deep Leakage from Gradients (DLG) attack demonstrates that individual training samples can be recovered from unprotected gradient updates, especially when batches are small and models are complex.

Attack Mechanism (DLG):

  • Attacker intercepts gradient g = ∇L(x,y; θ) shared during training
  • Attacker initializes dummy data (x', y') and dummy model parameters
  • Attacker compares dummy gradients to intercepted gradients and optimizes to minimize distance
  • After sufficient optimization iterations, x' converges to original training data x
  • Attack success depends on: batch size, model complexity, gradient resolution, input dimensionality

Vulnerability Factors:

  • Batch Size: Smaller batches = easier inversion (larger protection factor)
  • Model Complexity: Deeper/larger models leak more information in gradients
  • Input Dimensionality: High-dimensional inputs (images) more vulnerable than low-dim (tabular)
  • Gradient History: Multiple gradient updates amplify leakage
  • Gradient Precision: Float32 more leaky than quantized/compressed gradients

Defense Strategies:

  • Differential Privacy (DP-SGD): Add Gaussian noise to gradients. Standard deviation ε controls privacy-utility tradeoff.
  • Gradient Clipping: Limit gradient norms to reduce information leakage. Clip by global norm or layer-wise norm.
  • Secure Aggregation: Use cryptographic protocols so server never sees individual gradients.
  • Gradient Compression: Quantize/prune gradients to reduce information content (but not sufficient alone).
  • Larger Batch Sizes: Increase batch size to 128+ reduces per-sample gradient information.
  • Gradient Perturbation: Randomly zero-out some gradient dimensions before sharing.

Recommended DP-SGD Parameters:

  • For Low Risk (ε > 10): Standard training with minimal privacy loss. Use C=1.0, σ=0.5.
  • For Medium Risk (1 < ε ≤ 10): Moderate privacy. Use C=0.5, σ=1.0.
  • For High Risk (ε ≤ 1): Strong privacy guarantees. Use C=0.1, σ=2.0+ (accuracy may suffer).
