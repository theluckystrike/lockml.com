Secure Aggregation Protocol

Secure Aggregation (SecAgg) is a cryptographic protocol that enables federated learning while protecting individual client updates from the server. Only the aggregate model update is revealed, not individual gradients.

How It Works:

  • Masking: Each client adds a random mask to their gradient before transmission
  • Secret Sharing: Masks are split using Shamir's secret sharing (t-of-n threshold)
  • Aggregation: Server aggregates encrypted updates without seeing individual values
  • Unmasking: After enough clients aggregate, masks cancel out and true sum is revealed

Key Calculations:

  • Communication Overhead: Includes client updates, masks, and secret shares
  • Masking Overhead: Ratio of encrypted size to plaintext updates
  • Threshold (t): Minimum clients needed to recover aggregate (set to n/2 for Byzantine resilience)
  • Dropout Tolerance: Additional clients needed beyond threshold to handle failures
  • Bit Precision: 16-bit (FP16) saves bandwidth; 32-bit (FP32) standard; 64-bit (FP64) highest precision

Privacy Guarantees:

  • Server learns only the sum of updates, never individual gradients
  • Collusion of up to (n - t) clients + server cannot recover any individual update
  • Compatible with differential privacy for additional noise-based guarantees
  • Provides information-theoretic privacy (not computational)

Tradeoffs:

  • Higher communication and computation cost than plain FedAvg (typically 5-20x)
  • Synchronization challenges with dropout clients
  • Requires honest-but-curious threat model for server
